# Retrieval-Augmented Generation (RAG) AI Assistant

## Overview  
This project implements a Retrieval-Augmented Generation (RAG) AI assistant that combines a vector database with large language models to answer questions based on custom document corpora. The system uses LangChain for chaining prompts, document retrieval, and conversational memory.

## Features  
- Ingest and embed documents into a vector database (ChromaDB)  
- Retrieve relevant document chunks based on user queries  
- Generate natural language answers using state-of-the-art LLMs (OpenAI, Groq, Google Gemini)  
- Maintains conversation memory for multi-turn interactions
- Modular and extensible architecture for easy customization

## Tech Stack
- **LangChain**: Prompt management and LLM chaining
- **ChromaDB**: Vector database for document embeddings
- **Sentence Transformers**: Embedding model (all-MiniLM-L6-v2)
- **PyPDF2**: PDF document processing
- **Multiple LLM Providers**: OpenAI, Groq, Google Gemini

## Prerequisites
- Python 3.9 or higher
- pip package manager
- Valid API key for at least one LLM provider:
  - OpenAI (OPENAI_API_KEY)
  - Groq (GROQ_API_KEY)
  - Google Gemini (GOOGLE_API_KEY)

## Installation

1. Clone the repository:  
   ```bash
   git clone https://github.com/yourusername/your-repo-name.git
   cd your-repo-name
   ```

2. Create a virtual environment (recommended):  
   ```bash
   python -m venv env
   source env/bin/activate  # On Windows: env\Scripts\activate
   ```

3. Install dependencies:  
   ```bash
   pip install -r requirements.txt
   ```

4. Create a `.env` file in the project root directory based on `.env_example`:  
   ```bash
   cp .env_example .env
   ```

5. Add your API keys to the `.env` file:
   ```
   OPENAI_API_KEY=your_openai_key_here
   GROQ_API_KEY=your_groq_key_here
   GOOGLE_API_KEY=your_google_key_here
   ```

6. Prepare your documents:
   - Create a `data/` directory in the project root
   - Add .txt or .pdf files to the `data/` directory
   - The system will automatically load and process these documents

## Usage

### Running the Interactive Application

```bash
python app.py
```

This launches an interactive CLI where you can:
- Ask questions about your documents
- Receive context-aware answers generated by the LLM
- Maintain conversation history for follow-up questions
- Type `quit` to exit

### Example Interaction
```
Enter a question or 'quit' to exit: What is CRISPR gene editing?
Assistant: CRISPR-Cas9 is a revolutionary gene-editing technology that allows scientists...

Enter a question or 'quit' to exit: How does it work?
Assistant: CRISPR works by targeting specific DNA sequences...
```

## Key Components

### RAGAssistant Class
Main class that orchestrates the RAG pipeline:
- LLM initialization with support for multiple providers
- Vector database integration
- Prompt template management
- Conversational memory handling
- Query processing and response generation

### VectorDB Class
Manages document embeddings and retrieval:
- Text chunking with overlap
- Document embedding using Sentence Transformers
- ChromaDB collection management
- Similarity search functionality

## Environment Variables

Create a `.env` file with the following variables (see `.env_example`):

```
# LLM API Keys (set at least one)
OPENAI_API_KEY=your_key_here
OPENAI_MODEL=gpt-4o-mini

GROQ_API_KEY=your_key_here
GROQ_MODEL=llama-3.1-8b-instant

GOOGLE_API_KEY=your_key_here
GOOGLE_MODEL=gemini-2.0-flash

# Vector Database Configuration
CHROMADB_COLLECTION_NAME=rag_documents
EMBEDDING_MODEL=sentence-transformers/all-MiniLM-L6-v2
```

## API Keys and Security

- **Never commit `.env` files** to version control
- Use `.env_example` to document required variables without exposing secrets
- Store sensitive information in environment variables only
- For production, consider using secure secret management systems

## Limitations and Future Work
